# H2 外部検証 事前登録 v1.3(記述変数の追加とスキーマ凍結)

**上位文書:** `docs/IORN-009A_H2_preregistration_v1.0.md`(凍結 2026-08-23、コミット `6b77ee3`)、`..._v1.1.md`(コミット `3ca25e2`)、`..._v1.2.md`(コミット `a0029f9`)。**いずれも改変しない。** 四者を併せて読む。
**凍結日:** 2026-08-24
**凍結の証拠:** 本文書を追加したコミットのタイムスタンプ。**`data/h2_studies.json` への性能データ抽出はこのコミットより後に開始する。** 本文書はスキーマに関する最後の変更である(§D)。

## A. 追加内容 — 記述変数 `task_congruence`

**全研究に、タスクが本モデルの信号既知(SKE)前提とどう並ぶかを記録する。**

| 値 | 意味 |
|---|---|
| `ske` | 信号位置既知の検出タスク。モデルの前提(計画書 §2.1)に準拠。 |
| `search_or_location_uncertain` | 探索過程を含む、または病変位置が不確実。**モデルに対応する項が無い条件下での予測を求めることになる。** |

正本は `ptx/external.py` の `TASK_CONGRUENCE` と `StudyRecord.task_congruence`(**既定値を持たないフィールドとして宣言**したので、記録の欠落はレコード構築時に例外になる)。

**この変数は除外力を持たない。** `validate_study` は値が上記2値のいずれかであることだけを検査し(層が定義されるために必要)、**どちらの値であっても研究を落とさない**。C1–C6 とプール要件は v1.0 から変更しない。

### A.1 なぜ抽出開始前に入れるのか

タスク適合性は本モデルにとって**既知の異質性要因**である。$d'$ は信号既知前提で定義されており(計画書 §5.2)、探索過程に対応する項を持たない。したがって探索を含む研究に対する予測は、SKE 準拠の研究に対する予測とは性質の異なる外挿になる。この区別を**抽出前に記録変数として固定しておかなければ、不一致が出た後で「タスクが違ったから」と説明する余地が残る**。事後の言い分を事前の記録に変えることが本追加の目的である。

### A.2 選別に使わないことの担保(重要)

記述変数の追加は、それ自体が「不一致を層別で説明して逃げる」自由度になりうる。これを封じるため、以下を凍結する。

1. **H2 の主判定はプール全体で行う。** 層別は記述であり、**SKE 層のみのプールが主判定を置き換えることは無い。** v1.2 §D の3プール(C2 の版別)がそのまま主判定の対象である。
2. **層別結果は、有利でも不利でも報告する。** 各層について研究数・研究内 $\rho$ の分布・層内プール $\rho$ を出す。層が空の場合も空と報告する(`stratify_by_task_congruence` は空層も返す)。
3. **層別は機械的に行う。** 層の割り当ては `task_congruence` の値だけで決まり、$\rho$ を見てから群を作る余地は無い。
4. **層別の予測を先に書く(下記 A.3)。** 予測を先に書けば、層別は言い逃れではなく検証になる。

### A.3 層別についての事前予測(H2 の成功条件ではない)

**予測:** SKE 層の研究内 $\rho$ の中央値は、探索層の中央値**以上**である。

根拠は内在的である。モデルは探索過程を持たないため、探索が性能を条件依存に押し下げる場合、その押し下げ分は予測に現れない。逆に**探索層の $\rho$ が SKE 層より明確に高ければ、この層別の前提そのものが誤っていた**ことになり、その事実を報告する。

**この予測は H2 の成功条件に加えない。** 層別で H2 を救えないようにするためである(A.2-1)。予測の当否は解釈の材料としてのみ用いる。

## B. 解析への追記(v1.0 §5-3 の置き換え)

v1.0 §5-3(異質性)を次に置き換える。

> **異質性:** 研究間の $\rho$ の分布(最小・中央値・最大)を記述する。加えて **`task_congruence` による層別**を報告する:各層の研究数、研究内 $\rho$ の分布、層内プール $\rho$。メタ解析的な統合推定は行わない(研究数が少なく異質性が大きいため)。**層別は記述であり、主判定はプール全体で行う(v1.3 §A.2)。**

## C. 抽出開始前に確定した採否(機械判定のみ)

いずれも**性能データを一切見ずに**、包含基準の機械適用だけで決めた。**予想適合性による選別は行っていない。**

| 候補 | 判定 | 根拠(機械的) |
|---|---|---|
| CAND-01(Yu 2013、PMC3618092) | 抽出対象 | C1○ / C2 は `dose`・`reconstruction`・`lesion_size` の3軸 / C3 は条件点 ≥4 / C5 は 2AFC PC。`task_congruence = ske`。 |
| CAND-13(Leng 2013、PMC3724792) | **抽出対象(採用)** | C1○ / C2 は `dose`・`lesion_size` の2軸 / C3 は条件点8 / C5 は AUC。**位置不確実性は v1.2 の原則で条件軸に数えないが、C2 は残り2軸で満たされる。** 適合性の懸念(探索過程)は**除外理由にしない**:`task_congruence = search_or_location_uncertain` として記録し §B の層別で扱う。**指標は ROC AUC のみを用い、LROC AUC は使わない**(§5-4 の変換は等分散2正規 ROC の恒等式であり LROC には成立しない)。この扱いを登録簿の `notes` に記録する。 |
| CAND-14(Goo 2004、輝度×環境光) | **除外(確定)** | C2 で落ちる。環境光は v1.2 の原則で予測不能な軸(現行モデルにベイリンググレア項が無い)、輝度のみでは有効軸1本。除外理由は `unpredictable_axis_reason` が生成する定型文を用いる。 |

**CAND-13 を採用する理由の性質:** 「モデルに有利そうだから/不利そうだから」ではなく、**機械判定が通ったから**である。適合性が疑わしい研究を予想に基づいて外すことは、選択的検証そのものである。疑いは除外ではなく**記録と層別**で扱う。

**CAND-14 の除外が選別でないことの担保:** 除外は C2 の機械適用の結果であり、v1.2 の原則(2026-08-23 凍結)は本判定より前に凍結されている。加えて CAND-14 には C4 上の別問題(観察者がウィンドウ幅・レベルを自由調整する設計であり、ウィンドウ幅を固定入力とする本モデルでは条件を特定できない)があるが、**除外理由は C2 を主とする**(複数の理由を並べて事後的に補強しない)。この副次的懸念は候補表 `docs/h2_candidate_scan_v1.1.md` に記録済みである。

上記の判定は、抽出開始時に `data/h2_studies.json` の `studies` / `screened` に転記する(本コミットの時点では登録簿は空のままである)。

## D. スキーマの凍結宣言

**本文書をもってスキーマを凍結する。** `data/h2_studies.json` への抽出開始後、スキーマ(`StudyRecord` / `ObservedCondition` / `ScreenedStudy` の項目、および `TASK_CONGRUENCE`・`ALLOWED_*` の各語彙)は変更しない。

- C2 の語彙は v1.2 §B で既に打ち止め済み(変更はモデル拡張を伴う **v2.0** のみ)。
- 本文書以降のスキーマ変更も同様に **v2.0** を要する。抽出の途中でフィールドを足したくなった場合、それは**データを見てから記録項目を決めている**ことを意味するので行わない。必要なら `notes` に自由記述で残し、スキーマは動かさない。
