# H2 外部検証 事前登録 v1.2(改訂・打ち止め)

**上位文書:** `docs/IORN-009A_H2_preregistration_v1.0.md`(凍結 2026-08-23、コミット `6b77ee3`)、`..._v1.1.md`(凍結、コミット `3ca25e2`)。**v1.0・v1.1 は改変しない。** 本文書は v1.0 §0 の改訂手続きに従う追記であり、三者を併せて読む。
**改訂日:** 2026-08-23
**改訂の凍結:** 本文書を追加したコミットのタイムスタンプ。

## A. 改訂内容 — C2 を列挙から原則に移す

**条件軸として認めるのは、モデルの宣言済み入力スキーマに対応する軸に限る。**

v1.0 は条件軸を手で列挙し、v1.1 はそこに2語を足した。この方式は、語彙に載っていない条件軸を振った研究が現れるたびに改訂を要求する。改訂のたびに「今回の候補が通る語彙」を足していけば、それは基準ではなく後付けの選別になる。v1.2 は列挙を廃止し、次の原則に置き換える。

> 条件軸 $a$ が C2 に数えられるのは、$a$ が `ptx/condition.py` の `Acquisition` / `Reading` / `Task` の宣言済みフィールドに対応するとき、かつそのときに限る。

この原則が正しい形をしている理由は、**「モデルの入力である」= 「その軸を振ったときに何が起きるかをモデルが予測できる」**が同義だからである。C2 の目的は「モデルが予測できる条件軸が2本以上あり、研究内で順位を比較できること」に尽きる。予測できない軸を数えても検証にはならない。

**除外理由の定型文(v1.2 で凍結):**

> 現行モデルに対応する項が存在しないため、予測不能な軸は検証軸に数えない。

実装は `ptx/external.py` の `AXIS_TO_MODEL_INPUT` が正本であり、これが語彙そのものである。テストが両方向を検査する:**軸に対応フィールドが無いものは無く、対象フィールドに対応軸が無いものも無い**(`test_external.py`)。したがって語彙はモデル実装から導出され、**モデル自体を広げない限り語彙を広げられない**。

### A.2 軸として認めない宣言済み入力(2類別)

原則には2つの限定がある。いずれもフィールド単位の裁量ではなく類別で決まる。

1. **観察者効率パラメータ($\kappa$, $\eta_{\mathrm{cog}}$):** 宣言済み入力ではあるが、**文献から読み取る量ではなく §5.4 の区間で伝播させる量**である。これを条件軸として認めれば、こちらが当てはめている量を研究が「振った」と数えることになり、循環する。実装では `OBSERVER_EFFICIENCY_FIELDS`。
2. **参照校正フィールド(`reference_kernel`, `reference_sd_hu`, `reference_slice_mm`, `noise_scale_at_reference`):** 雑音スケールを既報の基準条件に固定するための入力であり、読影の条件ではない。実装では `CALIBRATION_FIELDS`。

### A.3 予測不能で認めない軸の例(網羅ではない)

| 軸 | 認めない理由 |
|---|---|
| 環境光・室内照度 | 現行モデルにベイリンググレア項が存在しない。予測不能。 |
| 病変位置の不確実性 | 探索過程に対応する項が存在しない($d'$ は信号既知前提)。予測不能。 |
| 読影者の経験年数・読影時間 | モデルに対応入力なし。$\eta_{\mathrm{cog}}$ に吸収される量であり、条件軸ではない。 |

これらを条件軸に含む研究は、**残りの軸だけで C2(≥2軸)を満たすかどうかで採否が決まる**。満たさない場合の除外理由は §A の定型文を用いる(`unpredictable_axis_reason` が文言を生成する)。

**他の基準(C1・C3・C4・C5・C6)、プール要件、H2 棄却条件は v1.0 から一切変更しない。**

## B. 改訂の打ち止め宣言

**C2 は原則ベース(モデルの宣言済み入力スキーマに閉じる)となったため、以後の語彙追加改訂は不要かつ行わない。** 新種の条件軸が現れた場合、それがモデルの入力に対応するなら v1.2 の原則で自動的に可となり、対応しないなら予測不能ゆえ不可となる。いずれも改訂を要しない。

**今後 C2 を変更する場合は v2.0 とし、モデル自体の拡張(該当する物理項の追加)と全面的な正当化を要する。** 語彙だけを動かす改訂は行わない。

## C. 本改訂が結果駆動でないことの宣言

改訂時点で実施済みの作業は、**候補文献のタイトル・抄録レベルの閲覧のみ**である。すなわち:

- **条件別の性能データ(AUC・PC・$d'$)の抽出は一切行っていない。**
- **図からの digitize は一件も行っていない。**
- **モデル予測との比較(順位相関の計算)は一件も行っていない。**
- したがって、本改訂によって採否が変わる研究の**検証結果は改訂時点で未知**である。

改訂時点で閲覧していた候補の一覧は `docs/h2_candidate_scan_v1.1.md`(CAND-01〜CAND-14)に記録されている。v1.1 改訂時点の一覧は `docs/h2_candidate_scan_v1.md` であり、両者とも改変しない。個別の研究名を改訂の根拠としては用いない(§A を参照)。

**本改訂が C2 を緩める方向であることの明示:** v1.2 は C2 を通る研究を増やす。緩和それ自体を隠さない。ただし C2 は「予測可能な条件軸が2本以上あるか」を判定するだけの門であり、**検証の負荷は C3(≥4条件点)と $\rho \ge 0.7$ の判定に置かれたままである**。緩めた門を通った研究が予測と合わなければ、H2 はその分だけ棄却に近づく。

## D. 解析への追記(v1.0 §5 / v1.1 §D の置き換え)

**感度分析は3プールで行う。** 主解析は v1.2 の基準で構成したプール。併記として、**v1.1 の語彙のみで構成したプール**と、**v1.0 の語彙のみで構成したプール(2軸厳格読み)**についても、研究内 $\rho$ とプール判定を報告する。

**成功条件への追加:** **3つの凍結版すべてで結論が同方向であること**(各プールで「研究単位の成功が過半数」かつ「プール $\rho \ge 0.7$」の判定が一致すること)を H2 の成功条件に加える。方向が一致しない場合は3プールすべてを並べて報告し、**どの版の基準が結論を作ったかを明示する**(隠さない)。

プールの切り分けは実装で機械的に行う(`ptx/external.py` の `pool_partition` が `v1_0_strict` / `v1_1` / `v1_2` と各改訂で新規に入った研究IDを返す)ため、事後の裁量が入らない。
